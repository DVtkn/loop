# Правила разработки и архитектура проекта Loop

> **Важно для всех ИИ-агентов (Google AI Studio, Cursor, Claude Code, Windsurf на Mac):**
> Пользователь разрабатывает проект одновременно через несколько агентов. Всегда строго соблюдайте следующие правила.

---

## 1. Обязательное документирование файлов (File Header & Responsibilities)

При создании или редактировании любых файлов **всегда** добавляйте или поддерживайте понятную шапку в начале файла с описанием:
- **Назначение файла**: за какую функциональность и домен отвечает файл.
- **Связи**: с какими частями системы он взаимодействует (бэкенд API, база данных Neon/Drizzle, клиентские хуки, состояние `CoupleContext`).
- **Ключевые экспорты**: краткое назначение ключевых компонентов, хуков, функций или роутов.

**Пример шапки для TypeScript-файла:**
```typescript
/**
 * @file: src/components/dashboard/PairStatusCard.tsx
 * @description: Карточка статуса пары на главном дашборде.
 * @responsibilities:
 *  - Отображает дни вместе, текущие XP и уровень близости пары
 *  - Обрабатывает кнопку быстрого пинга / тапа партнёра (Quick Touch)
 *  - Синхронизируется с CoupleContext и API /api/couple/ping
 */
```

## 2. Архитектура проекта

Проект представляет собой Full-Stack PWA-приложение для двоих (Express backend + React frontend на Vite).

### Клиентская часть (`src/`)
- `src/main.tsx`, `src/App.tsx` — точка входа React-приложения, маршрутизация и обёртки контекстов.
- `src/components/` — экранные представления (`AuthView`, `DashboardView`, `ChatView`, `ReportView`, `TestsView`) и модульные UI-компоненты по папкам (`dashboard/`, `tests/`, `radar/`, `photo/`, `ui/`).
- `src/context/` — глобальное состояние пары (`CoupleContext`), хуки авторизации, XP, тачей и синхронизации.
- `src/api/` — типизированные клиентские клиенты к бэкенду (`auth`, `pair`, `couple`, `chat`, `photos`, `tests`).
- `src/data/questionBank.ts` — единственный источник истины для вопросов психологических тестов (Готтман, ЭФТ, Big Five и др.).
- `src/shared/tests.registry.ts` — синхронизированный реестр категорий и тестов.
- `src/utils/` — алгоритмы расчёта совместимости (`psychologyEngine`), Web Push (`pushManager`), локальное хранилище.

### Серверная часть (`src/server/`)
- `src/server/app.ts` — главное Express-приложение, подключение промежуточных слоёв (security, cors, cookie-parser, json) и монтирование роутеров `src/server/modules/*`.
- `src/server/index.ts` — локальная точка входа dev-сервера.
- `src/server/core/` — конфигурация переменных окружения (`config.ts`), логгер, базовые типы.
- `src/server/db/` — схема Drizzle (`schema.ts`) и клиент Neon PostgreSQL (`client.ts`).
- `src/server/modules/` — изолированные доменные модули (каждый содержит `*.routes.ts` и `*.service.ts`):
  - `auth/` — регистрация, вход, JWT-сессии, bcrypt.
  - `pairing/` — отправка и принятие инвайтов партнеров.
  - `tests/` — психометрический расчёт (24 шкалы, Big Five, генерация couple-отчетов).
  - `chat/` — ИИ-психолог «Сова» и диалоги.
  - `photos/` — общие фотоальбомы и капсулы времени.
  - `couple-data/` — общее состояние пары, заметки, вишлисты.

## 3. Критические соглашения и инварианты

1. **Единый источник истины для тестов**: Изменения в структуре шкал и вопросах тестов должны одновременно отражаться в `src/data/questionBank.ts`, `src/shared/tests.registry.ts` и `src/server/modules/tests/psychometrics.calc.ts`.
2. **Безопасность и CORS/Iframe**: Сервер обслуживает как автономный прод (Vercel), так и iframe-превью в AI Studio. Заголовки безопасности в `src/server/app.ts` должны сохранять поддержку `frameAncestors` и не блокировать работу в Safari/iOS.
3. **Проверка перед завершением работы**:
   - `npm run test:tsc` (или `tsc --noEmit`) должен проходить без ошибок.
   - Юнит-тесты `npm run test` (Vitest) должны быть зелеными.

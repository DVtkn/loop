# SECURITY.md — Политика безопасности и секретов проекта Loop

Данный документ определяет требования к управлению секретами, ключами и окружениями для обеспечения информационной безопасности приложения **Loop**.

---

## 1. Политика разделения секретов (Prod vs Dev)

Все секретные ключи, токены аутентификации и строки подключения **категорически запрещено** дублировать между Production и Development окружениями. В Production запрещено использовать предсказуемые значения по умолчанию или резервные подстроки (fallback strings).

| Имя переменной | Назначение | Обязательность в Production | Поведение при отсутствии в Prod |
| :--- | :--- | :--- | :--- |
| **`DATABASE_URL`** / **`NEON_DATABASE_URL`** | Строка подключения к PostgreSQL (Neon) с SSL | **ОБЯЗАТЕЛЬНО** | Сервер немедленно завершает работу (`FATAL`), предотвращая работу на временном диске. |
| **`JWT_SECRET`** | Секретный ключ подписи и проверки JWT-токенов | **ОБЯЗАТЕЛЬНО** | Сервер немедленно завершает работу (`FATAL`), предотвращая подделку токенов. |
| **`GROQ_API_KEY`** | Ключ доступа к API ИИ-психолога (Сова) | Рекомендуется | Переключение на встроенный детерминированный движок правил `psychologyEngine`. |
| **`VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY`** | Ключи для Web Push уведомлений | Рекомендуется | Браузерные пуш-уведомления отключаются, доставка касаний работает через SSE. |

## 2. Гарантии безопасности при смене JWT_SECRET

1. **Изоляция окружений**:
   - `/.env` (локальное dev-окружение): использует локальный ключ разработки.
   - Vercel (Production Environment Variables): использует отдельный криптостойкий 64-символьный `JWT_SECRET` (генерируется через `openssl rand -hex 32`).

2. **Аннулирование скомпрометированных сессий (Session Invalidation)**:
   - При смене `JWT_SECRET` на Vercel все ранее выданные токены мгновенно теряют валидность.
   - Серверный метод `jwt.verify()` отклоняет их с ошибкой `JsonWebTokenError: invalid signature` и возвращает статус `HTTP 401 Unauthorized`.
   - Пользователи будут перенаправлены на экран входа, а несанкционированный доступ со старыми токенами полностью исключён.

## 3. Защита от несанкционированного доступа (IDOR Prevention)

1. Все эндпоинты, работающие с данными союза (`/api/couple/*`, `/api/pet/*`, `/api/tests/*`, `/api/analytics/*`, `/api/chat/*`, `/api/photos/*`), защищены middleware `requirePairOwnership`.
2. Ключ союза `pairKey` вычисляется сервером из верифицированного JWT-токена пользователя и его подтверждённого партнёра: `[login, partnerLogin].sort().join('_')`. Попытка запросить данные чужой пары пресекается статусом `403 Forbidden`.

---

## 4. Чек-лист развёртывания нового стенда (Checklist)

При деплое приложения на Vercel или другой хостинг:

1. В панели управления Environment Variables задать:
   - `NODE_ENV=production`
   - `DATABASE_URL="postgresql://..."` (Neon connection string с SSL)
   - `JWT_SECRET="<уникальный_64_символьный_hex_ключ>"`
   - `GROQ_API_KEY="..."`
   - `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`
2. Убедиться, что сервер стартует без критических ошибок в логах Vercel Functions.
3. Проверить ответ эндпоинта `GET /api/health` — статус базы данных должен быть `"ok"`.
